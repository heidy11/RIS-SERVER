Guía de la laptop: instalación, arranque y troubleshooting

Todo lo necesario para usar la laptop en la prueba con el tomógrafo y para replicar la instalación en otra laptop o PC con Windows.

Hoja rápida: prueba con el tomógrafo

Para tener a mano frente al equipo. Cada paso tiene más detalle más abajo.

1. Arrancar (al llegar)

cd D:\RIS-NUESTRO\RIS-SERVER
.\pacs-lab\scripts\iniciar-ris.ps1
  • Esperar a que abra el navegador con el RIS (la primera vez del día, cerca de un minuto).
  • No cerrar las dos ventanas que se abren (backend y frontend).
  • Conectar la laptop a la red del tomógrafo y volver a correr el script: al final muestra la IP en esa red.

2. Datos para el técnico del tomógrafo

DatoValor
AE Title del servidor de worklistWORKLIST
IPLa que muestra el script en la red del tomógrafo
Puerto11112

Pedirle además el AE Title propio del tomógrafo, su IP y su puerto DICOM. Si el equipo tiene botón Verify, Echo o Test, probarlo: debe dar OK.

3. Registrar el tomógrafo en el RIS

  • Equipos → + Nuevo: modalidad CT, AE Title del tomógrafo (exacto, distingue mayúsculas), su IP y su puerto. Guardar.
  • Botón Probar conexión en la fila del equipo: debe responder.

4. La prueba

  • Pacientes → crear un paciente. Recepción → cita para hoy, modalidad CT.
  • Simular primero desde la laptop (reemplazar por el AE real del tomógrafo):
.\pacs-lab\scripts\simular-tomografo.ps1 -AeEquipo AE_DEL_TOMOGRAFO
  • En el tomógrafo: abrir la worklist y actualizar (Reload, Refresh o Query). Debe aparecer el paciente.
Ojo con la fecha: los equipos solo muestran las citas de hoy. Las citas de prueba cargadas antes son de otro día; para recrearlas con la fecha de hoy:
node pacs-lab/scripts/mwl.js purge
node pacs-lab/scripts/mwl.js seed

Soporte remoto: si algo no se resuelve, la laptop tiene AnyDesk y acceso a internet. Abrir AnyDesk y pasar el código para revisarlo en vivo.

1. Qué queda instalado

Al terminar la instalación, la laptop funciona como un pequeño centro de imágenes completo, sin depender de internet ni de los servidores en la nube.

ComponentePara qué sirveDónde corre
RIS (frontend)El sistema que usa el personal: recepción, citas, órdenes, equipos.Navegador: http://localhost:5173
BackendGuarda los datos y manda cada cita a la worklist del PACS.Puerto 5000
MongoDBBase de datos del RIS (pacientes, citas, usuarios).Contenedor Docker ris-mongo
PACS (DCM4CHEE)Servidor DICOM: la worklist que consulta el tomógrafo.Contenedores Docker pacs-lab-*

El flujo: se agenda una cita en el RIS → el backend la envía al PACS en segundos → el tomógrafo consulta la worklist del PACS y la cita aparece en su pantalla, con los datos del paciente ya cargados.

2. Requisitos

  • Windows 10 u 11, de 64 bits.
  • Unos 10 GB libres. Si el disco C: está justo, instalar el proyecto en otra partición (en la laptop de referencia se usó D:).
  • Internet durante la instalación, para descargar programas e imágenes de Docker. Para usar el sistema después, no hace falta.
  • Un usuario con permisos de administrador (solo para abrir los puertos del firewall).
  • Virtualización habilitada en la BIOS (Docker la necesita; en casi todas las laptops modernas ya viene habilitada).

3. Instalación paso a paso

Todos los comandos van en PowerShell (menú Inicio → escribir "PowerShell"). Se indica cuándo hace falta abrirla como administrador.

Paso 1 — Docker Desktop

  • Descargar desde https://www.docker.com/products/docker-desktop/ e instalar con las opciones por defecto (dejar marcado "WSL 2").
  • Reiniciar la PC si el instalador lo pide.
  • Abrir Docker Desktop desde el menú Inicio y esperar a que la ballena de la barra de tareas deje de moverse.

Verificar (el primero muestra una versión; el segundo, "Versión predeterminada: 2"):

docker --version
wsl --status

Paso 2 — Git

Descargar desde https://git-scm.com e instalar con las opciones por defecto. Verificar:

git --version

Paso 3 — Node.js

  • Descargar la versión LTS desde https://nodejs.org e instalar con las opciones por defecto.
  • Cerrar PowerShell y abrir una nueva, para que reconozca el programa recién instalado.

Windows bloquea por defecto los scripts de PowerShell, y npm es uno. Habilitarlos solo para este usuario (responder S si pregunta):

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

Verificar:

node --version
npm --version

Paso 4 — Descargar el proyecto

D:
mkdir RIS-NUESTRO
cd D:\RIS-NUESTRO
git clone https://github.com/heidy11/RIS-SERVER.git
git clone https://github.com/MED-RIS/RIS.git

Quedan dos carpetas: RIS-SERVER (backend y PACS) y RIS (frontend). Instalar las dependencias de cada una (tarda unos minutos):

cd D:\RIS-NUESTRO\RIS-SERVER
npm install
cd D:\RIS-NUESTRO\RIS
npm install

Paso 5 — Configurar el backend

cd D:\RIS-NUESTRO\RIS-SERVER
Copy-Item .env.example .env
notepad .env

En el Notepad, cambiar estas líneas y guardar:

LíneaQué poner
JWT_SECRETUna clave larga al azar (comando abajo). Nadie la escribe nunca; es interna del servidor.
ADMIN_EMAILEl correo con el que se va a entrar al RIS.
ADMIN_PASSWORDLa contraseña para entrar al RIS (distingue mayúsculas).
MWL_ENABLEDtrue — sin esto las citas nunca llegan a la worklist.
MPPS_ENABLEDtrue — para que el RIS reciba el estado del estudio desde el equipo.

Para generar el JWT_SECRET, correr esto y pegar el resultado:

-join ((48..57)+(65..90)+(97..122) | Get-Random -Count 48 | % {[char]$_})
Importante: el usuario administrador se crea la primera vez que arranca el backend, con el correo y la contraseña de este archivo. No reutilizar contraseñas de ejemplo ni de otros sistemas.

Paso 6 — Base de datos

docker run -d --name ris-mongo -p 127.0.0.1:27017:27017 --restart unless-stopped -v ris-mongo-data:/data/db mongo:6.0

La primera vez descarga la imagen. El 127.0.0.1 hace que la base de datos solo se pueda usar desde la propia laptop, no desde la red.

Paso 7 — PACS

cd D:\RIS-NUESTRO\RIS-SERVER
npm run pacs-lab:up

La primera vez descarga varias imágenes (unos minutos). Después esperar 30 a 60 segundos y verificar; tiene que responder {"count":0} o un número:

curl.exe http://localhost:8080/dcm4chee-arc/aets/WORKLIST/rs/mwlitems/count

Opcional: cargar tres citas de prueba (CT, DX y US) con la fecha de hoy y listarlas:

node pacs-lab/scripts/mwl.js seed
node pacs-lab/scripts/mwl.js list

Paso 8 — Firewall (como administrador)

Abrir PowerShell como administrador (clic derecho → Ejecutar como administrador) y correr:

New-NetFirewallRule -DisplayName "RIS-PACS DICOM" -Direction Inbound -Protocol TCP -LocalPort 11112 -Action Allow
New-NetFirewallRule -DisplayName "RIS web" -Direction Inbound -Protocol TCP -LocalPort 5173 -Action Allow
New-NetFirewallRule -DisplayName "RIS backend" -Direction Inbound -Protocol TCP -LocalPort 5000 -Action Allow

El 11112 lo usa el tomógrafo; el 5173 y el 5000 sirven para entrar al RIS desde otra PC de la red. Opcional, para que la laptop responda al ping:

New-NetFirewallRule -DisplayName "Permitir ping" -Protocol ICMPv4 -IcmpType 8 -Direction Inbound -Action Allow

Paso 9 — Primer arranque

cd D:\RIS-NUESTRO\RIS-SERVER
.\pacs-lab\scripts\iniciar-ris.ps1

Se abre el navegador en el RIS. Entrar con el correo y la contraseña del paso 5. Si entra, la instalación está completa. Siempre verificar el login antes de dar la instalación por terminada. Si dice "Credenciales inválidas", correr npm run reset-admin (ver troubleshooting).

4. Arranque del sistema (uso diario)

Cada vez que se prende la laptop, un solo comando:

cd D:\RIS-NUESTRO\RIS-SERVER
.\pacs-lab\scripts\iniciar-ris.ps1

El script hace, en orden:

  1. Abre Docker Desktop si no estaba abierto y espera a que esté listo.
  2. Levanta el PACS y la base de datos, y espera a que el PACS responda.
  3. Abre dos ventanas nuevas: la del backend y la del frontend. Tienen que quedar abiertas mientras se usa el sistema; cerrarlas apaga esa parte.
  4. Abre el RIS en el navegador.
  5. Avisa si falta abrir algún puerto en el firewall.
  6. Muestra la IP de la laptop, los datos para el técnico del tomógrafo y la dirección para entrar desde otra PC.
Nota: la primera vez del día el frontend tarda cerca de un minuto en compilarse antes de abrirse.

Arranque manual (si el script no está disponible)

Primero abrir Docker Desktop desde el menú Inicio y esperar a que cargue. Después, en una PowerShell (dejarla abierta):

cd D:\RIS-NUESTRO\RIS-SERVER
npm run pacs-lab:up
docker start ris-mongo
npm start

Y en otra PowerShell (también dejarla abierta):

cd D:\RIS-NUESTRO\RIS
npm run build -- --mode lan
npm run preview -- --host --port 5173 --strictPort

Apagar

Cerrar las ventanas del backend y del frontend. Los contenedores del PACS y la base de datos se pueden dejar: se detienen solos al cerrar Docker Desktop o apagar la laptop.

Actualizar a la última versión

cd D:\RIS-NUESTRO\RIS-SERVER
git pull
npm install
cd D:\RIS-NUESTRO\RIS
git pull
npm install

Después cerrar las ventanas del backend y del frontend y volver a correr iniciar-ris.ps1.

Entrar al RIS desde otra PC de la red

En el navegador de la otra PC: http://<IP de la laptop>:5173. iniciar-ris.ps1 muestra la dirección exacta al final. Requiere los puertos 5173 y 5000 abiertos (paso 8).

5. Prueba con el tomógrafo

Sin el tomógrafo (simulación)

  1. En el RIS: Pacientes → crear un paciente. Recepción → agendar una cita para hoy, modalidad CT.
  2. Simular la consulta que hace el tomógrafo:
cd D:\RIS-NUESTRO\RIS-SERVER
.\pacs-lab\scripts\simular-tomografo.ps1

El simulador consulta la worklist por DICOM, igual que el equipo real, y muestra el paciente, el número de orden y el horario. Otras modalidades o equipos, y la salida completa para diagnosticar:

.\pacs-lab\scripts\simular-tomografo.ps1 -Modalidad US -AeEquipo US01
.\pacs-lab\scripts\simular-tomografo.ps1 -Completo

Con el tomógrafo real

En el tomógrafo (lo configura el técnico del equipo)

Agregar un servidor de worklist (según la marca aparece como Worklist, RIS, HIS/RIS o Basic Worklist):

DatoValor
AE Title del servidorWORKLIST
IPLa IP de la laptop en la red del tomógrafo (la muestra iniciar-ris.ps1)
Puerto11112

Anotar también el AE Title propio del tomógrafo. Si el equipo tiene botón Verify, Echo o Test, probarlo: debe dar OK.

En el RIS

  1. Equipos → + Nuevo: modalidad CT, el AE Title del tomógrafo (exacto, distingue mayúsculas), su IP y su puerto DICOM. Guardar.
  2. Botón Probar conexión en la fila del equipo: si responde, la laptop llega al tomógrafo.
  3. Con un solo tomógrafo registrado, toda cita CT nueva se le asigna sola. Agendar una cita CT para hoy. Las citas anteriores al registro quedan con la estación de prueba (CT01).
  4. En el tomógrafo, abrir la worklist y actualizar: debe aparecer el paciente.

Opcional: que las imágenes vuelvan al PACS

En el equipo se configura un destino de almacenamiento (Storage o Archive): AE Title DCM4CHEE, la misma IP y puerto 11112. Si soporta MPPS, apuntarlo al mismo destino y el RIS marca la cita como en curso o terminada solo. No hace falta para probar la worklist.
